Forecast-informed option Start from the selected benchmark Add short-term rainfall forecast Use rain amount × probability × horizon Consider changing irrigation timing
Key discussion: do we measure forecast value against A, B or C? Steve's point is important: in limited-water situations, SWD/crop-model scheduling may not represent normal sugarcane farmer practice, so C should not automatically be assumed as the benchmark.
How the visual works
1
Select a benchmarkA/B use an example fixed cycle. C uses SWD to decide when irrigation is due.
2
Show irrigation eventsThe SWD chart is retained so we can see crop-water status when those events occur.
3
Check the forecastAt each benchmark irrigation event, look ahead and check rainfall amount and probability.
4
Discuss irrigate or waitThe page only flags a possible delay. It does not claim this is the final CLOVER rule.
Important: automation itself does not change irrigation dates in this simple visual. A and B therefore use the same fixed-cycle timing; the difference between them is operational/labour context. The real benchmark and farm assumptions need to be agreed by the team and farmers.
